# Ответы на контрольные вопросы (лаб. №24)

**1. Для чего нужен хук useState? Как обновить состояние на основе предыдущего значения?**
`useState` хранит локальное состояние функционального компонента между рендерами и возвращает пару
`[значение, функция-сеттер]`; вызов сеттера планирует повторный рендер. Если новое значение зависит
от старого, в сеттер передают функцию: `setItems(prev => prev.filter(i => i.id !== id))`. Так React
подставит актуальное значение, даже если несколько обновлений сгруппированы в один рендер.

**2. Что такое побочный эффект? Примеры из проекта.**
Побочный эффект — действие, выходящее за рамки вычисления JSX: работа с внешними API, DOM, таймерами,
хранилищем. В проекте: чтение/запись `localStorage` (`useLocalStorage`), таймер имитации загрузки,
debounce-таймер автосохранения, изменение `document.title`, подписка на `beforeunload`.

**3. Как работает массив зависимостей в useEffect? Что будет, если оставить его пустым?**
React запускает эффект после рендера, если хотя бы одна зависимость изменилась (сравнение `Object.is`).
Без массива эффект выполняется после каждого рендера. Пустой массив `[]` — только один раз после
монтирования; функция очистки вызовется при размонтировании.

**4. Как загрузить данные из localStorage при монтировании?**
```js
useEffect(() => {
  const raw = localStorage.getItem('clothing-store:cart');
  setItems(raw ? JSON.parse(raw) : INITIAL_CART);
}, []);
```
В проекте это делается внутри `useLocalStorage` с задержкой 1 с (имитация сервера) и защитой
`try/catch` от повреждённого JSON.

**5. Почему нельзя вызывать хуки внутри условий или циклов?**
React связывает состояние с хуком по порядку вызова при каждом рендере. Если хук вызвать в условии,
порядок может измениться, и состояние «перепутается» между хуками. Поэтому хуки вызываются только на
верхнем уровне компонента или пользовательского хука (правило `rules-of-hooks`).

**6. Разница между localStorage и sessionStorage?**
Оба — синхронные хранилища строк «ключ–значение» в рамках origin (~5 МБ). `localStorage` хранит данные
бессрочно и общий для всех вкладок; `sessionStorage` живёт до закрытия вкладки и у каждой вкладки свой.

**7. Ленивая загрузка начального состояния через функцию-инициализатор.**
```js
const [items, setItems] = useState(() => {
  const raw = localStorage.getItem('clothing-store:cart');
  return raw ? JSON.parse(raw) : INITIAL_CART;
});
```
Функция вызывается только при первом рендере, поэтому чтение и `JSON.parse` не повторяются при
каждом рендере.

**8. Как отладить бесконечный цикл перерендеров из-за useEffect?**
Причина обычно — эффект меняет состояние, от которого сам зависит, или в зависимостях объект/функция,
создаваемые заново на каждом рендере. Нужно: проверить массив зависимостей (React DevTools / Profiler,
`console.log` в эффекте), использовать функциональное обновление `setX(prev => …)`, мемоизировать
зависимости через `useMemo`/`useCallback`, добавить условие выхода (например, `if (isLoading) return`).

**9. Как сохранить объект/массив в localStorage и восстановить его?**
`localStorage` хранит только строки: `localStorage.setItem(key, JSON.stringify(items))` и
`JSON.parse(localStorage.getItem(key))`. Чтение стоит оборачивать в `try/catch` и проверять тип
результата (в проекте — проверка `Array.isArray`).

**10. Что будет, если прочитать состояние сразу после setState? Рендер мгновенный?**
Нет. `setState` лишь планирует обновление; в текущем вызове функции переменная хранит старое значение
(снимок рендера). React группирует (batching) обновления и выполняет рендер позже. Для вычислений на
основе нового значения используют функциональное обновление или `useEffect`.

**11. Как имитировать асинхронную загрузку с сервера через setTimeout в useEffect?**
```js
useEffect(() => {
  const timer = setTimeout(() => {
    setItems(readStorage() ?? INITIAL_CART);
    setIsLoading(false);
  }, 1000);
  return () => clearTimeout(timer);
}, []);
```
Пока `isLoading === true`, интерфейс показывает спиннер «Загрузка корзины с сервера…».

**12. Какую функцию очистки можно вернуть из useEffect? Пример отмены таймера.**
Функция, возвращаемая из эффекта, вызывается перед повторным запуском эффекта и при размонтировании.
Из проекта (debounce автосохранения):
```js
useEffect(() => {
  if (isLoading) return undefined;
  const timer = setTimeout(() => writeStorage(key, value), 500);
  return () => clearTimeout(timer);
}, [key, value, isLoading]);
```
Также очистка снимает обработчик `beforeunload` и возвращает исходный `document.title`.

**13. Контролируемые и неконтролируемые компоненты форм.**
Контролируемый: значение поля хранится в состоянии React (`value={form.title}` +
`onChange`), React — единственный источник истины; удобно валидировать и сбрасывать форму (так
сделаны `CartForm` и редактирование строки). Неконтролируемый: значение хранит DOM, читается через
`ref` или `FormData` при отправке (`defaultValue`, `useRef`) — меньше кода, но меньше контроля.

**14. Как реализовать горячую клавишу (Enter для добавления)?**
Проще всего обернуть поля в `<form onSubmit>` — Enter в поле ввода отправит форму (так работает
добавление). Либо обработать `onKeyDown`: в режиме редактирования строки
`if (e.key === 'Enter') save(); if (e.key === 'Escape') onCancelEdit();`. Для глобальных клавиш —
`window.addEventListener('keydown', …)` в `useEffect` с удалением обработчика в очистке.

**15. Оптимизация большого списка.**
`useMemo` — кешировать отфильтрованный/отсортированный список и статистику (в проекте
`visibleItems`, `stats`); `React.memo` — не перерисовывать строки с неизменными props (`CartItemRow`),
при этом колбэки стабилизируются через `useCallback`; стабильные `key`; виртуализация
(`react-window`, `@tanstack/react-virtual`) — рендерить только видимые строки; пагинация;
`useDeferredValue` для поиска.

**16. Debounce для автосохранения при вводе. Пример.**
Каждое изменение запускает таймер, а очистка эффекта отменяет предыдущий — сохранение произойдёт
через 500 мс после последнего изменения:
```js
function useDebouncedSave(key, value, delay = 500) {
  useEffect(() => {
    const timer = setTimeout(() => {
      localStorage.setItem(key, JSON.stringify(value));
    }, delay);
    return () => clearTimeout(timer);
  }, [key, value, delay]);
}
```
