# Клиент: корзина интернет-магазина одежды (лаб. №24–25)

React-приложение (Vite) для управления корзиной интернет-магазина одежды.
В лаб. №24 данные хранились в `localStorage`. В лаб. №25 клиент работает с REST API из корня
репозитория (Node.js + Express + PostgreSQL + JWT, лаб. №21–23) через axios.

## Запуск

1. Запустите сервер (из корня репозитория, см. [README](../README.md)): PostgreSQL, миграции, сиды, затем
   `npm run dev`. Сервер слушает `http://localhost:3000`.
2. Запустите клиент:

```bash
cd client
npm install
copy .env.example .env   # Linux/macOS: cp .env.example .env
npm run dev              # http://localhost:5173
npm run build            # production-сборка в dist/
npm run lint             # oxlint
```

Переменные окружения (`client/.env`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `VITE_API_URL` | Базовый адрес API | `http://localhost:3000/api` |
| `VITE_API_DELAY_MS` | Искусственная задержка каждого запроса, мс (для проверки спиннеров) | `0` |

После изменения `.env` перезапустите `npm run dev`.

Для входа можно зарегистрироваться в приложении или взять администратора из сида
(`admin@shop.local` / `Admin123!`).

## Функциональность

- **Аутентификация**: вход и регистрация (`POST /api/auth/login`, `/register`). JWT хранится
  в `localStorage` и подставляется в каждый запрос интерцептором axios. Если сервер ответил 401
  (токен истёк), клиент выходит из сессии и показывает форму входа с сообщением.
- **Загрузка корзины (GET)**: при монтировании `useEffect` вызывает `fetchCart()`. Пока идёт
  загрузка, показан спиннер. При ошибке выводится сообщение и кнопка «Повторить». Запрос отменяется
  через `AbortController`, если компонент размонтирован (например, при выходе).
- **Добавление (POST)**, оптимистично: позиция сразу появляется в списке с временным ID
  `temp-<Date.now()>`, затем уходит запрос. При успехе временная запись заменяется позицией
  из ответа сервера с реальным `id`. При ошибке позиция удаляется и появляется уведомление.
  Если такой товар того же размера уже в корзине, увеличивается его количество (как на сервере).
- **Редактирование (PUT)**, оптимистично: количество меняется кнопками `−`/`+`, размер и количество —
  в режиме «Изменить» (Enter — сохранить, Escape — отменить). При ошибке позиция откатывается
  к прежнему состоянию.
- **Удаление (DELETE)**, оптимистично: позиция сразу убирается. При ошибке она возвращается
  на прежнее место. Так же работает «Очистить корзину» (`DELETE /api/cart`).
- **Фоновые запросы**: у позиции, по которой идёт запрос, показан маленький спиннер, и кнопки
  заблокированы. В блоке «Итого» видно «Сохранение…» или «Синхронизировано».
- **Ошибки**: `getErrorMessage()` различает отсутствие ответа (сервер выключен, нет сети, CORS),
  таймаут, 5xx и ответы сервера с `{ error: { message } }`. Ошибки CRUD-операций выводятся
  всплывающими уведомлениями (автоскрытие через 4 с).
- **Дополнительное улучшение — поиск на сервере с debounce**: поле поиска по каталогу отправляет
  `GET /api/products?search=…&category=…` только через 400 мс после последнего ввода
  (`useDebounce`). Если параметры изменились до прихода ответа, устаревший запрос отменяется
  `AbortController`, поэтому старый ответ не перезапишет новый.
- **Дополнительное улучшение — пагинация каталога**: товары загружаются по 6 штук
  (`GET /api/products?limit=6&offset=…`). Кнопка «Показать ещё (осталось N)» догружает следующую
  страницу и добавляет её к уже показанным. Над списком написано «Показано X из Y». При смене
  поиска или категории список начинается с первой страницы, а незавершённая догрузка отменяется.
  Если догрузка не удалась, рядом с кнопкой появляется ошибка, а сама кнопка становится «Повторить».
- Из лаб. №24 сохранены фильтрация и сортировка загруженной корзины на клиенте, статистика,
  `document.title` с числом единиц в корзине и `React.memo` для строк.

## Схема взаимодействия с сервером

```
 Браузер (React, :5173)                                    Сервер (Express, :3000)        PostgreSQL
 ─────────────────────                                    ────────────────────────       ──────────
 LoginForm ── login() ──── POST /api/auth/login ─────────▶ bcrypt.compare, jwt.sign ─────▶ Users
           ◀──────────────── { token, user } ─────────────
 localStorage['clothing-store:token'] = token

 api.js: интерцептор добавляет  Authorization: Bearer <token>  к каждому запросу
                                                           cors() → auth (jwt.verify) → контроллер
 CartForm ── fetchProducts() ─ GET /api/products?search=&limit=6&offset=
                                                         ─▶ findAndCountAll(iLike) ─────▶ Products
          ◀──────────────── { data: [...], meta: { total, hasMore } } ──
 useCart  ── fetchCart() ───── GET /api/cart ─────────────▶ CartItem.findAll ────────────▶ CartItems
          ── addCartItem() ─── POST /api/cart/items ──────▶ транзакция: create/increment
          ── updateCartItem()─ PUT /api/cart/items/:id ───▶ проверка размера/остатка, update
          ── deleteCartItem()─ DELETE /api/cart/items/:id ▶ destroy
          ── clearCart() ───── DELETE /api/cart ──────────▶ destroy where userId
          ◀────────── 2xx { data } | 4xx/5xx { error: { status, message } } ─────────────
 401 → событие auth-expired → useAuth выходит из сессии
```

## Структура

```
src/
  api.js                     — axios-инстанс, интерцепторы (токен, 401), функции API, getErrorMessage
  App.jsx                    — шапка, выбор между формой входа и корзиной, уведомления
  hooks/useAuth.js           — вход/регистрация/выход, хранение JWT, реакция на 401
  hooks/useCart.js           — загрузка корзины и CRUD с оптимистичным обновлением и откатом
  hooks/useDebounce.js       — debounce значения (поиск по каталогу)
  hooks/useNotifications.js  — очередь всплывающих уведомлений
  components/LoginForm.jsx   — форма входа/регистрации
  components/CartList.jsx    — основной компонент корзины: состояния загрузки/ошибки, фильтры, сортировка
  components/CartForm.jsx    — поиск по каталогу на сервере (debounce + AbortController),
                               «Показать ещё» (limit/offset) и добавление
  components/CartItemRow.jsx — строка корзины, редактирование (React.memo)
  components/CartStats.jsx   — блок «Итого» и индикатор синхронизации
  components/Toasts.jsx      — уведомления с автоскрытием
  data/catalog.js            — категории, форматирование цены
  utils/validateItem.js      — проверка размера и количества перед отправкой
```
