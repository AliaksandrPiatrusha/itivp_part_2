# Материалы для отчёта — лабораторная работа №5 (ветка lab25)

**Тема:** взаимодействие React-приложения с сервером.
**Вариант:** система управления заказами и корзиной для интернет-магазина одежды.

## 1. Цель работы

Освоить отправку HTTP-запросов из React-приложения к REST API, обработку асинхронных состояний
(загрузка, ошибка, успех) и обновление интерфейса по полученным данным. Задача — интегрировать
клиентскую часть курсового проекта с серверным API.

## 2. Описание приложения

React-клиент (Vite, папка `client/`) управляет корзиной покупателя интернет-магазина одежды.
Данные хранятся на сервере из лаб. №21–23 (Node.js + Express + PostgreSQL/Sequelize, JWT).
Клиент лаб. №24 хранил корзину в `localStorage`. Теперь всё хранение перенесено на REST API.

Реализовано:

| Требование | Реализация |
|---|---|
| Получение списка (GET) | `useCart`: `GET /api/cart` при монтировании, спиннер, сообщение об ошибке и кнопка «Повторить» |
| Добавление (POST) с оптимистичным обновлением | `useCart.addItem`: временный ID `temp-<Date.now()>`, после ответа замена на реальный `id`, при ошибке удаление и уведомление |
| Удаление (DELETE) | `useCart.removeItem`: позиция сразу убирается, при ошибке возвращается на прежнее место; «Очистить корзину» — `DELETE /api/cart` |
| Редактирование (PUT) | `useCart.updateItem`: количество (−/+) и размер, при ошибке откат к снимку |
| JWT | вход/регистрация, токен в `localStorage`, подстановка интерцептором axios, при 401 выход |
| CORS | middleware `cors` на сервере (`CORS_ORIGIN`) |
| Дополнительное улучшение №1 | **поиск по каталогу на сервере** (`GET /api/products?search=`) с **debounce 400 мс**; устаревшие запросы отменяет **AbortController** (он же отменяет загрузку корзины при размонтировании) |
| Дополнительное улучшение №2 | **пагинация** каталога (`?limit=6&offset=…`, в ответе `meta.total` и `meta.hasMore`) с кнопкой «Показать ещё» |

Изменения на сервере в этой работе:
- `src/app.js` — подключён `cors()` со списком разрешённых origin;
- `src/models/products.model.js` — параметр `search` (ILIKE по `title` и `color`), страницы
  через `findAndCountAll` с `limit`/`offset`;
- `src/controllers/products.controller.js` — проверка `limit` (1–100) и `offset` (≥ 0),
  в ответе `meta: { total, limit, offset, hasMore }`;
- `seeders/20261028120000-more-products.js` — ещё 14 товаров, всего в каталоге 18;
- `src/controllers/cart.controller.js` — `PUT /api/cart/items/:id` принимает `size` и/или
  `quantity`, проверяет остаток на складе (409) и дубли размера (409). `POST`/`PUT` возвращают `item`;
- `src/models/cart.model.js` — позиция корзины содержит `category`, `color`, `sizes`, `stock`, `createdAt`.

## 3. Схема взаимодействия React-приложения с сервером (текстовое описание)

1. Пользователь вводит email и пароль в `LoginForm`. `useAuth.login()` вызывает
   `POST /api/auth/login`. Сервер сверяет пароль (`bcrypt.compare`) и возвращает JWT.
   Клиент сохраняет токен и пользователя в `localStorage`.
2. Все запросы идут через экземпляр axios из `src/api.js` с `baseURL = VITE_API_URL`.
   Перехватчик запросов добавляет заголовок `Authorization: Bearer <token>`.
3. Браузер отправляет запрос на другой origin (`:5173` → `:3000`). Для `PUT`/`DELETE` и заголовка
   `Authorization` сначала уходит preflight `OPTIONS`. Middleware `cors` отвечает
   `Access-Control-Allow-Origin: http://localhost:5173`.
4. На сервере запрос проходит `express.json()` → роутер → `auth` (проверка JWT) → контроллер →
   слой моделей (Sequelize) → PostgreSQL. Ответ приходит в формате `{ data }` или
   `{ error: { status, message } }`.
5. При монтировании `CartList` хук `useCart` загружает корзину (`GET /api/cart`) и показывает
   спиннер, затем список или ошибку.
6. При добавлении, изменении и удалении состояние сначала меняется локально (оптимистично), затем
   уходит `POST`/`PUT`/`DELETE`. Ответ сервера подтверждает изменение (замена временного ID)
   или вызывает откат и уведомление.
7. `CartForm` ищет товары в каталоге: ввод проходит через `useDebounce` (400 мс), затем
   `GET /api/products?search=&category=&limit=6&offset=0`. При изменении параметров предыдущий
   запрос отменяется `AbortController`. Кнопка «Показать ещё» запрашивает следующую страницу
   с `offset` = число уже загруженных товаров и добавляет её к списку. Пока `meta.hasMore`
   равно `true`, кнопка остаётся видна.
8. Если любой запрос с токеном получил 401, перехватчик ответов генерирует событие `auth-expired`.
   `useAuth` очищает сессию и показывает форму входа с сообщением «Сессия истекла».

Графический вариант схемы приведён в [README.md](README.md#схема-взаимодействия-с-сервером).

## 5. Скриншоты — как получить

Подготовка: запустить сервер (`npm run dev` в корне) и клиент (`npm run dev` в `client/`),
открыть `http://localhost:5173`, войти (`admin@shop.local` / `Admin123!` или новый пользователь).

| № | Скриншот | Как получить |
|---|---|---|
| 1 | Процесс загрузки (спиннер) | В `client/.env` поставить `VITE_API_DELAY_MS=2000`, перезапустить `npm run dev`, обновить страницу. Видны «Загрузка корзины с сервера…» и «Загрузка каталога…». Затем вернуть `0` |
| 2 | Список загруженных элементов | Корзина с 2–3 позициями и блоком «Итого» |
| 3 | Добавление — до | Выбрать товар в каталоге, указать размер и количество, до нажатия «Добавить в корзину» |
| 4 | Добавление — после | Новая позиция в списке и уведомление «… добавлен в корзину». С задержкой 2000 мс можно поймать промежуточное состояние «сохраняется…» с временным ID |
| 5 | Удаление | До и после нажатия «Удалить», уведомление «… удалён из корзины» |
| 6 | Редактирование | Режим «Изменить» (размер + количество), затем результат |
| 7 | Ошибка при недоступности сервера | Остановить сервер (Ctrl+C) и нажать «Обновить» над корзиной: «Не удалось загрузить корзину. Сервер недоступен…» с кнопкой «Повторить» |
| 8 | Откат оптимистичного обновления | Сервер остановлен, корзина уже загружена: нажать «Удалить» или «+». Позиция возвращается, появляется красное уведомление |
| 9 | Дополнительное улучшение (поиск + debounce) | Набрать «джин» в поиске по каталогу. В DevTools → Network (фильтр `products`) виден один запрос `?search=джин` после паузы, а не по запросу на букву. При быстром вводе с задержкой API ранние запросы отмечены как `(canceled)` |
| 9а | Пагинация — до и после | Каталог без поиска: «Показано 6 из 18» и кнопка «Показать ещё (осталось 12)». После нажатия — «Показано 12 из 18». В Network видны запросы `limit=6&offset=0` и `limit=6&offset=6` |
| 10 | Токен в запросах (по желанию) | DevTools → Network → любой запрос `/api/cart` → Request Headers → `Authorization: Bearer …`; Application → Local Storage → `clothing-store:token` |

## 6. Выводы (черновик)

В ходе работы клиент курсового проекта переведён с локального хранилища на собственный REST API.
Запросы вынесены в отдельный модуль `api.js` на базе axios. JWT-токен автоматически добавляется
перехватчиком, а ответ 401 централизованно завершает сессию. Состояния загрузки, ошибки и успеха
хранятся явно, поэтому интерфейс всегда показывает, что происходит: спиннер, сообщение с кнопкой
повтора или данные. Оптимистичное обновление с временным ID и точечным откатом делает добавление,
изменение и удаление мгновенными для пользователя и сохраняет согласованность с сервером при
ошибках. Пагинация через `limit`/`offset` с кнопкой «Показать ещё» не загружает весь каталог сразу.
Серверный поиск с debounce уменьшает число запросов при наборе текста, а AbortController
исключает гонки ответов и обновление состояния после размонтирования. Для работы клиента с другого
origin на сервере настроен CORS. Вынос логики в пользовательские хуки (`useCart`, `useAuth`,
`useDebounce`) позволил почти не менять компоненты при замене `localStorage` на API.
